- 정의를 바꾸면 날짜와 이유를 11절 개정 기록에 남기고, 이미 낸 결과를 새 정의로 다시 계산한다.

## 1. 사례의 구성

각 사례는 `cases/NN_이름/case.py` 하나다.

| 구성 | 뜻 |
|---|---|
| `META` | 원래 이슈, 엔진, 사실 종류, 생산자→소비자 경계, 발동 조건, 사례 종류, 증상, 예상 검출 시점, 비교 방식 |
| `setup()` | 입력과 모델을 만든다. 무작위 값은 고정된 시드로 만든다 |
| `defect(ctx)` | 원래 결함의 기전을 담은 판 |
| `fixed(ctx)` | 원래 수정의 기전을 담은 판 |
| `reference(ctx)` | 사실을 풀어 쓴 참조 계산. 느려도 뜻이 분명한 계산이다 |
| `probe(ctx)` (선택) | 실제 엔진이 같은 입력에서 어떻게 하는지 관찰한다. 판정에는 쓰지 않고 기록만 한다 |

**사례 종류:**
- **실엔진 재현:** 설치된 엔진 코드를 그대로 불러 원래 결함을 다시 낸 것
- **기전 모사:** 같은 기전을 최소 코드로 다시 만든 것

기전 모사를 실엔진 재현이라고 부르지 않는다.

## 2. "재현"의 정의

아래 셋이 모두 성립하면 재현이다.
1. **결함 판이 틀린다.** 결함 판의 출력이 참조 계산에서 허용 오차 밖으로 벗어난다.
2. **결함 판이 조용하다.** 결함 판을 실행하는 동안 예외가 없고, Python 경고도 없고, WARNING 이상의 로그도 없다.
   - 결함과 무관하다고 확인된 로그는 사례의 `META["ignore_logs"]`에 정규식으로 적고, 제외한 사실도 기록한다.
3. **수정 판이 맞다.** 수정 판의 출력이 참조 계산의 허용 오차 안에 든다.

## 3. 허용 오차

| 비교 방식 | 판정 |
|---|---|
| `exact` | 정확히 같아야 한다 |
| `fp32` | 최대 절대 오차 ≤ 1e-5 + 1e-4 × max(1, 참조 최대 절댓값) |
| `loose` | 최대 절대 오차 ≤ 2e-3 + 2e-2 × max(1, 참조 최대 절댓값). Triton 커널이 fp32 곱셈을 TF32로 할 수 있는 경우에 쓴다 |
| `bf16` | 최대 절대 오차 ≤ 1e-2 + 2e-2 × max(1, 참조 최대 절댓값) |
| `noise` | 모델 출력용. 두 조건을 모두 만족해야 한다. (1) 결함 판의 참조 대비 차이가 수정 판 차이의 10배 이상이다. (2) 수정 판 차이는 커널이 다른 두 올바른 경로 사이의 잡음 수준이다 |

`noise` 방식은 Gemma 2 측정에서 배운 것이다. bf16에서는 커널만 다르고 수학이 같은 두 경로도 최상위 토큰이 1% 어긋났다(`issue_track/gemma2_softcap/PROTOCOL.md` 개정 1). 모델 출력에서는 이런 잡음의 크기를 먼저 재고, 그 위에서 결함의 차이를 본다.

## 4. "검출"의 정의 (도구와 기존 수단에 똑같이 적용)

- 한 수단이 사례를 검출했다는 것은 두 가지가 함께 성립한다는 뜻이다.
  - 결함 판에서 오류, 경고, 실패 판정을 낸다.
  - 수정 판에서는 내지 않는다.
- **검출 시점:** 서버 시작(적재) / 실행 중 / 시험(CI) / 사후(평가나 비교)
- **자세함 등급:**
  - 0: 틀렸다는 것만 안다. 예: 점수 하락, 출력 차이.
  - 1: 어느 부품(모듈이나 함수)에서 갈라졌는지 안다.
  - 2: 어느 경계에서 어떤 사실(형식, 위치 기준, 유효 범위, 성질 등)이 어긋났는지 이름을 댄다.

## 5. "오탐"의 정의

정상 실행에서 검사 수단이 오류나 경고를 내면 오탐이다. 정상 실행 묶음은 다음과 같다.
- Qwen3-4B (bf16, int4)
- Gemma 2 2B (eager)
- 이 벤치마크의 모든 수정 판

## 6. 기존 탐지 수단 기록 (로드맵 1.6)

사례마다 아래를 `META["baseline"]`과 결과 파일에 적는다.
- **(a) 발동 조건:** 장비, 기능 플래그, 길이, 몇 번째 대화인지, 배치 구성
- **(b) 표준 평가가 발동하는가:** 기준은 vLLM 야간 평가(2026-07 공개)다.
  - 장비: H200, B200, MI300X, MI355X
  - 평가: GSM8K, GPQA, AIME, BFCL
  - 조건: 기본 설정, 한 차례 대화

  이 조건이 사례의 발동 조건을 포함하는지 본다.
- **(c) 발동한다면 점수가 움직이는가:** 모델 경로 사례는 작은 평가 세트로 실측하고, 나머지는 판단한다.
- **(d) 실무상 참조 구현이 있는가:** 그 경로와 맞대 볼 구현이 실제로 있는지 판단한다.

판단은 가설을 모르는 평가자에게 이슈 본문과 중립적인 질문을 주고 맡긴다. 결과에는 "판단"이라고 표시한다.

## 7. 기록

- `run_case.py`는 사례 하나를 실행해 `results/<사례>.json`에 적는다.
  - 판마다의 출력 차이 지표, 로짓이면 최상위 토큰 일치율
  - 조용함 기록: 예외, 경고, 로그
  - 재현 판정
  - probe 기록
  - 소요 시간
  - 환경: torch·transformers 버전, GPU
- `run_all.py`는 모든 사례를 각각 별도 프로세스로 돌리고 `results/results.md`에 표로 모은다.

## 11. 개정 기록

- **2026-09-23, 개정 1:** 허용 오차에 `fp8`을 더했다.
  - 판정: 최대 절대 오차 ≤ 1e-2 + 5e-2 × max(1, 참조 최대 절댓값)
  - 이유: 사례 #2의 수정 판은 FP8 데이터를 다시 양자화하므로, 반올림 오차가 fp32나 bf16 허용 오차보다 크다.
  - 결과를 보기 전에, 사례를 설계하는 단계에서 더했다.
- **2026-09-23, 제외 목록 1:** 사례 #10에서 torch `create_block_mask`의 `_compile` 사용 중단 예고를 제외했다.
  - 같은 예고가 수정 판에서도 똑같이 나와, 결함과 무관하다.
  - 제외 전 판정은 "재현 아님"이었다. 결함 판은 틀렸고 수정 판은 맞았지만, 이 예고 때문에 조용함 판정이 실패했다.
