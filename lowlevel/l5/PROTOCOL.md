# M19 L5 규약: 배포 전 점검을 3·4차 재현 사례로 재기 (L5.1, 2026-09-27)

로드맵 M19 L5. 연구자 결정 "위 계획을 채택할거야"(2026-09-27)로 채택한 4단계 계획의 1단계다. 이 문서는 L5.2의 결과를 보기 전에 쓴다. 결과를 본 뒤에는 7절(결과)만 채운다. 바꾸는 것이 있으면 6절에 날짜와 이유를 적는다.

## 1. 묻는 것

- **질문(계획 2단계):** 동결한 연구 도구(`lowlevel/l2`)의 일반 비교를 버그의 조건 위에서 돌리면, 도구를 만들 때 본 적 없는 실제 버그가 드러나는가.
- **"배포 전 점검"이 여기서 뜻하는 것:** 설치형 entail이 아니라 연구 도구의 무거운 비교다. 실행 방식끼리의 비교, 디코드 대 prefill, 같은 양자화를 돌리는 기준과의 층 대조, 연산 점검, 유한성 검사가 여기에 든다. entail은 끈다(`ENTAIL` 없음).
- **오염 확인:** 연구 도구를 만들고 검증한 로우레벨 16건(`lowlevel/l2/RESULTS.md`의 L4 표)에 3·4차 사례는 없다. 1·2차 사례 가운데 적어도 다섯(vl56655, tf46612, vl48895, sg21843, vl42016)은 들어 있어서 쓰지 않는다.

## 2. 대상 (동결)

3·4차 재현에서 재현된 17건이다. 재현되지 않은 3건(vl43962, tf45491, vl25800)은 뺀다. 부류와 수준은 3·4차 눈가림 평정의 합의다(`testbed/results/m18/replay3/results.json`, `testbed/results/m19/replay4/results.json`). "기대 경계"는 심사 때 적은 값이다.

**도구 적용을 가르는 규칙(결과 전에 정함):**
- 도구가 모는 것: vLLM의 텍스트 생성(방식 여덟)과 이미지 탐침(base·fp16 방식), transformers의 텍스트 생성(`run_hf.py`), 층 대조(vLLM 대 transformers 기준), 연산 점검(`op_specs.py`에 명세가 있는 연산).
- **도구 없음(입력 종류):** 사례의 모델이나 조건이 위 어느 것으로도 들어가지 않는다. 확산 파이프라인, 오디오, 영상과 영상 처리기, 객체 검출, LoRA 어댑터, KV 커넥터, 서버 파서, GGUF 적재가 여기에 든다.

- 넷 모두 분모에 남기고 "드러나지 않음"으로 센다. 종류별로도 따로 적는다. 이 목록이 L5.4에서 자리를 고르는 자료가 된다.

## 3. 사례별 실행 (동결)

도구는 동결한 사본 `lowlevel/l5/frozen_l2/`에서 돌린다. 탐침은 도구 자신의 것(`probes.py`: 텍스트 여섯, 멀티모달 모델이면 `L2_IMAGES=1`로 이미지 셋)만 쓴다. 사례의 재현 입력은 도구에 넣지 않는다. 도구를 고쳐야 하기 때문이다. "사례의 조건"은 엔진 판, 모델, 보고가 준 엔진 설정(자료형), 메모리 설정이다. 문턱은 도구의 기본값(확신 뒤집힘 1.0, 확률 이동 0.25, 층 대조 R1·R3)이다.

| 사례 | 판(가상 환경) | 모델 | `L2_ENGINE`과 그 밖의 설정 | 비교 |
|---|---|---|---|---|
| vl33560 버그 | vLLM 0.16.0 (`vllm0160`) | `~/models/replay4/RedHatAI__Qwen3-8B-NVFP4` | `{"dtype": "float16", "max_model_len": 1024, "gpu_memory_utilization": 0.85}` (보고의 조건: Turing의 자동 자료형 float16) | `run_vllm.py` 방식 여덟 |
| vl33560 고쳐짐 | vLLM 0.30.0 (`vllm`) | 같음 | 같음 | 같음 |
| vl43602 버그 | vLLM 0.22.0 (`vllm0220`) | Qwen/Qwen3-VL-2B-Instruct(HF 캐시 스냅샷) | `{"max_model_len": 2048, "gpu_memory_utilization": 0.8, "limit_mm_per_prompt": {"image": 1, "video": 0}}`, `L2_IMAGES=1` (사례 스크립트의 설정) | 방식 여덟 + 층 대조 |
| vl43602 고쳐짐 | vLLM 0.30.0 | 같음 | 같음 | 같음 |

| vl27390 고쳐짐 | vLLM 0.30.0 | 같음 | 같음 | 방식 여덟 + 층 대조 |

- **층 대조:** 엔진 덤프는 그 사례의 가상 환경에서 `layers.py vllm <모델> <폴더> <엔진 설정>`으로 한다(메모리 설정은 위와 같음). 기준은 `gpu` 가상 환경(transformers 5.17.0)에서 `layers.py hf`를 float32(CPU)와 bfloat16(GPU)으로 돌리고, `layers.py compare`로 비교한다. vl33560은 층 대조를 하지 않는다. 체크포인트가 compressed-tensors NVFP4라서 `dequant.py`에 형식이 없고, 8B의 float32 기준(약 32 GB)이 WSL 메모리(23 GB)를 넘는다. 그래서 "기준 없음"으로 적는다.
- 층 덤프(`.pt`)는 비교가 끝나면 지운다. 디스크 여유 때문이다. `meta.json`과 비교 결과는 남긴다.
- 실행 순서는 vl33560 버그 → 고쳐짐 → vl43602 버그 → 고쳐짐 → vl27390 버그 → 고쳐짐 → 층 대조다. GPU에는 한 번에 하나만 올린다.

## 4. 측정 정의와 셈법 (동결)

- **드러남(버그 판):** 셋 가운데 하나라도 있으면 드러난 것이다.
  1. `run_vllm.py`의 비교 하나라도 DIFFERS다(`compare.verdict`).
  2. 비유한 로그확률 알림이 있다(`nonfinite_logprobs`가 비어 있지 않음).
  3. `layers.py compare`에서 `first_diverging_layer`나 `first_diverging_layer_tok`가 나온다.
- **제자리:** 드러낸 신호가 가리키는 자리가 기대 경계의 구성 요소와 같으면 제자리를 짚은 것이다. 신호와 자리의 대응은 다음과 같다.
  - `graph_*` → compile·CUDA 그래프 경로
  - `native_*` → 커스텀 연산의 커널 경로
  - `triton_attn_*` → 어텐션 백엔드
  - `chunk_*` → 청크 prefill
  - `spec_*` → 추측 디코딩
  - `fp16_*`와 `image_fp16_vs_base` → float16 경로
  - `batched_vs_alone` → 배치
  - `cache_*`와 `supplied_*` → 프리픽스 캐시
  - `decode_vs_prefill` → 디코드 경로
  - 비유한 로그확률 → 자리 없음(유한성). 어느 방식에서 났는지만 적는다.
  - 층 대조의 첫 층 N → N번 층
  - 기대 경계별로 제자리가 되는 신호는 이렇다.
    - vl33560(Marlin GEMM): 층 대조뿐인데 기준이 없으므로 제자리가 될 신호가 없다.
    - vl43602(compile 경로): `graph_*`.
    - vl27390(멈춘 이유): 대응하는 신호가 없다.
- **틀린 경보:** 고쳐진 판에서 드러남의 셋 가운데 하나라도 있으면 틀린 경보다.
- **다른 자리 경보:** 버그 판에서 기대 경계와 다른 자리의 신호가 나오면 따로 적는다. 그것이 다른 실제 결함인지 틀린 경보인지는 판정하지 않고, 원인도 찾지 않는다. 결함 찾기는 요청할 때만 한다.
- **시간:** 방식별 엔진 적재 시간(도구의 `load_s`)과 사례별 벽시계 시간을 적는다.
- **셈:**
  - 부류 안 11건을 분모로 드러남과 제자리를 센다. 로우레벨(D) 7건과 I 4건은 따로 센다.
  - 도구가 돈 사례만의 수도 함께 적는다.
  - 부류 밖이거나 평정이 갈린 6건은 "짚음"(부류 밖에서 드러남)으로 따로 센다.
  - 틀린 경보는 돈 고쳐진 판의 수를 분모로 센다.
  - 도구 없음, 모델 없음, 그 판에서 돌지 않음은 종류별로 센다.

## 5. 주의와 규칙

- **상한이다.** 실험하는 쪽이 버그를 이미 알고 사례의 조건(판, 자료형)을 골랐다. 실제 배포에서는 그 조건을 돌리지 않을 수 있다. 탐침은 사례 입력이 아니라 도구 자신의 것이라서, 입력이 방아쇠인 사례(예: vl43602는 compile 경로의 이미지 요청)에서는 상한보다 낮게 나올 수 있다. 도구의 이미지 탐침은 base와 fp16 방식에만 들어간다.
- **표본이 작다.** 부류 안에서 도구가 도는 것은 한 건이다. 비율을 일반화하지 않는다.
- **도구를 고치지 않는다.** 판 호환 때문에 방식이나 덤프가 실패하면 실패로 적는다. 도구가 스스로 "mode failed to run"을 남긴다. 고쳐서 다시 돌리지 않는다. 메모리 설정(`L2_ENGINE`)은 3절의 값에서 바꾸지 않는다. 메모리 부족으로 실패하면 실패로 적는다.
- **새 모델이나 가상 환경을 받지 않는다.** C 드라이브 여유가 5 GB 아래로 내려가면 멈추고 알린다(시작 때 9.8 GB).
- **에이전트는 쓰지 않는다.**
- **도구의 동결:** `lowlevel/l2`의 `.py` 20개와 `hf_modes_override.json`을 `lowlevel/l5/frozen_l2/`에 복사했다. sha256은 `lowlevel/l5/frozen_l2.sha256`에 있다. 앞 16자리 예시: `compare.py` c85e2302a4f45319, `run_vllm.py` bd807e5453fa7497, `vllm_worker.py` c1e5e7c2bd4e4bec, `layers.py` ef08879e223393d2, `probes.py` 91321e2b43ef5964.
