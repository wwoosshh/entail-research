# 코드북 v2 (초안, 검토용)

- 작성: 2026-09-25. 로드맵 R4(로우레벨 의미 손실 연구)의 첫 산출물이다. 연구자 지시 "진행해"(첫 행동: 정체·시점 부류를 사실로 정의하고 E3의 stale-state 두 건을 시험 문제로 세운다).
- v1(`CODEBOOK_v1.md`)은 이슈를 기전 부류 A~E와 사실 종류 10가지로 나눈다. v2는 그 가운데 **A(부품 사이 사실의 어긋남)를 다섯 부류로 세분**하고, 부류마다 "사실로 만들려면 무엇이 있어야 하는가"의 틀을 붙인다. v1의 나머지(포함 기준, 확인됨/불명, 증상과 조용함, 표시)는 그대로 쓴다.
- 이 문서는 측정 도구다. 어느 부류가 많아야 한다는 기준은 두지 않는다. 판정은 데이터로 한다.
- 다섯 부류의 이름은 연구자가 2026-09-25에 정했다: 단위·기준, 형식·입도, 소유·수명, 정체·시점, 경로.

## 1. 부류를 정하는 틀

부류 하나가 "사실"이 되려면 다섯 칸이 채워져야 한다(`LIBRARY_DESIGN.md` 5절, 6절의 규칙과 같다).

| 칸 | 뜻 |
|---|---|
| 선언하는 쪽 | 그 값의 뜻을 만드는 부품과 자리(파일, 자료 구조, 호출) |
| 읽는 쪽 | 그 뜻을 전제로 값을 쓰는 부품과 자리 |
| 불변식 | 두 쪽이 같아야 하는 조건. 코드가 아니라 말로 적는다 |
| 어긋남의 모양 | 누락(선언이 안 닿음) / 불일치(다르게 가정) / 시점 오류(옛 값을 읽음) |
| 해소 수단 | 어긋남을 되돌리는 측정된 방법이 있으면 적는다. 없으면 `broken`으로 보고한다 |

분류 순서: 먼저 v1의 A인지 본다(각 부품은 제 규약 안에서 맞았는가). A이면 아래 다섯 가운데 하나를 고른다. 둘에 걸치면 주된 것을 고르고 다른 하나는 표시로 남긴다. 다섯 어디에도 안 들면 A-기타로 두고 짧은 이름을 제안한다.

블라인드 평정에는 중립 글자 F, G, H, I, J를 쓴다(아래 순서). 이름과 가설은 알려 주지 않는다.

## 2. 다섯 부류

### F. 단위·기준 (unit·reference)

- **정의:** 같은 수를 두 부품이 다른 단위, 기준점, 스케일로 읽는다. 위치의 기준(절대·청크 상대), 회전 기저와 스케일링, 잠재 공간 배율, 길이의 단위(토큰·블록·바이트).
- **어휘의 사실:** `Rotary`, `Positions`, `LatentScale`, `Valid`(길이의 단위는 `KvExtent.granularity`).
- **사례:** fd-rope(RoPE 기저가 덮어쓰기에서 사라짐), rolebench 05(청크 상대 대 절대 위치), 12(토큰 수로 위치를 정해 한 칸 밀림), fd-vae(VAE 배율).
- **어긋남의 모양:** 누락(기저가 안 닿음), 불일치(기준점이 다름).

### G. 형식·입도 (format·granularity)

- **정의:** 값의 배치, 자료형, 양자화 단위, 어휘의 크기와 번호, 토큰의 종류처럼 "이 바이트들이 무엇을 뜻하는가"가 두 부품에서 다르다.
- **어휘의 사실:** `Layout`, `Quantized`, `Coverage`(설정 키). 아직 없는 사실 셋은 아래 4절.
- **사례:** rolebench 01, 02(배치·스케일), 16(양자화 dtype), E3 sglang#39626(커널 타일이 양자화 블록보다 큼), transformers#48967(토크나이저 어휘 32,000 대 모델 100,000), vllm#58138(패딩의 토큰 종류가 안 쓰임).
- **어긋남의 모양:** 불일치가 대부분.

### H. 소유·수명 (ownership·lifetime)

- **정의:** 버퍼나 산출물이 누구 것이고 언제까지 유효한가를 두 부품이 다르게 안다. 약한 참조로만 잡힌 버퍼, 캡처된 그래프가 붙든 주소, 다른 소유자에게 재사용된 메모리.
- **어휘의 사실:** `Epoch.owner`, `Assumed`(재사용 조건). 소유자와 수명을 값으로 든 사실은 아직 없다.
- **사례:** rolebench 09(그래프 재사용이 포인터만 비교), 11(빈 입력으로 특화된 컴파일 결과의 가드 없는 재사용), E3 sglang#37606(깨지는 CUDA 그래프가 약한 참조만 들어 다른 데이터가 덮음).
- **경계:** sglang#37606은 엔진 한 부품 안의 메모리 수명이라 E3에서 "밖"으로 분류했다. 소유자가 선언되는 자리가 있어야 사실이 된다. 이 부류는 선언 자리가 있는지부터 사례로 확인해야 한다.

### I. 정체·시점 (identity·epoch)

- **정의:** 저장되거나 캐시된 항목이 **무엇을 대신하는지**(정체)와 **언제의 것인지**(시점)를 만든 쪽과 읽는 쪽이 다르게 안다. 해시 키, 블록 해시, 세션 번호, 버퍼 판본이 여기 든다.
- **어휘의 사실:** `Epoch`(버퍼 판본). 정체(무엇을 대신하는가)를 값으로 든 사실은 아직 없다. → 3절의 제안.
- **사례:** E3 vllm#49377, vllm#49449(아래 3절), rolebench 14(빔 서치가 표준 캐시만 재정렬하고 순환 상태는 옛 순서), 10(위치 카운터를 참조로 들고 제자리 증가 뒤에 읽음), vllm#18955(V0의 오래된 계산 블록 추적, 2025-06 수정).
- **어긋남의 모양:** 시점 오류(옛 정체를 그대로 믿음)가 전형이다.

### J. 경로 (path)

- **정의:** 같은 선언이 한 실행 경로에서는 지켜지고 다른 경로에서는 버려진다. 백엔드, prefill 대 decode, 컴파일 대 eager, 스트리밍 대 일괄, 사양별 커널.
- **어휘의 사실:** `ModelProps`와 능력표(경로별 처리 여부), `Template`(도구 파서).
- **사례:** fd-softcap(sdpa·torch_native·flashinfer가 softcap을 버림; sglang#33915), rolebench 06(사용자 마스크를 주면 창이 꺼짐), 08, 17.
- **주의:** 능력표의 행은 경로마다 재야 한다. "읽는다"는 한 경로가 읽었다는 뜻이지 모든 경로가 읽는다는 뜻이 아니다(`probes.py` 머리말 4항).

## 3. 정체·시점을 사실로: `Identity` (어휘 v5 제안, 연구자 확인 전)

### 3.1 사례 (E3에서 재현, entail 1.0.0은 통과시킴)

vllm#49377 "토큰 절단이 `Request.block_hashes`를 낡게 둔다"(2026-07-21, 열림)와 vllm#49449 "스트리밍 세션 재구성이 낡은 prefix 캐시 블록 해시를 남겨 틀린 출력"(2026-07-22, 열림, 라벨 bug). 같은 결함, 같은 코드 경로. 수정 PR 셋(#49145, #49619, #49448)은 모두 병합되지 않고 닫혔다. vLLM 0.30.0에 그대로 있다(`testbed/results/r4/identity_probe.json`, `testbed/results/m10/e3/cases/vl49449_off.json`).

| 칸 | 내용 (vLLM 0.30.0, 코드에서 읽음) |
|---|---|
| 선언하는 쪽 | `Request.update_block_hashes`(`vllm/v1/request.py:278`)가 `block_hashes[i]`를 채운다. 값은 해시 블록 i의 토큰들을 앞 블록의 해시에 이어 해시한 것이다(`get_request_block_hasher`, `kv_cache_utils.py:812`). 뜻: "블록 i의 KV는 이 토큰들의 것이다" |
| 읽는 쪽 | `KVCacheManager.get_computed_blocks`(`kv_cache_manager.py:265`)가 이 해시로 prefix 캐시를 찾는다. KV 이벤트와 오프로드도 이 해시를 정체로 믿는다(이슈 본문) |
| 불변식 | 모든 i에 대해 `block_hashes[i]` = 요청이 **지금** 든 블록 i 토큰의 해시. 그리고 저장된 해시 수 ≤ 지금 든 토큰 수 ÷ 블록 크기 |
| 어긋남의 모양 | 시점 오류. `Scheduler._update_request_as_session`(`scheduler.py:1570`)이 `_all_token_ids`를 `num_computed_tokens` 뒤로 자르고 새 청크를 붙인 뒤 `update_block_hashes()`를 부르는데, 이 함수는 덧붙이기만 하고 해셔는 `len(block_hashes) × B`부터 다시 시작한다. 버려진 샘플 토큰이 해시 블록을 완성했으면 그 해시가 남고, 뒤의 해시는 모두 거기에 이어진다 |
| 결과 | 옛 토큰과 같은 프롬프트의 다른 요청이 새 토큰으로 계산된 KV를 받는다. E3 끝까지 실행: 후보 요청이 16 토큰을 캐시에서 맞고 첫 토큰이 참조(다른 cache_salt로 재계산)와 다르다(`,` 대 `\n`). 경고 없음 |
| 해소 수단 | 첫 어긋난 해시부터 버리고 `update_block_hashes()`로 다시 붙인다. 캐시 항목을 잊는 것뿐이라 재계산 비용만 든다(닫힌 PR #49619와 같은 방향) |

### 3.2 사실 정의 (제안)

- **이름:** `Identity` (종류 TIME; MAPPING과 걸침). 필드: `of`(무엇의 정체인가, 닫힌 목록: `kv_block`), `index`(몇 번째), `key`(저장된 열쇠, 바이트), `covers`(그 열쇠가 대신하는 토큰 수).
- **선언 쪽 값:** 엔진이 저장한 열쇠(`block_hashes[i]`). 출처 `engine`, 확실성 `verified`.
- **관측 쪽 값:** 요청이 지금 든 토큰으로 다시 만든 열쇠. 출처 `data`.
- **규칙 `identity_stale`:** 저장된 열쇠 ≠ 지금 토큰의 열쇠 → 해소 수단이 등록되어 있으면 `resolved`(열쇠를 버리고 다시 만듦), 없으면 `broken`(보고하고 계속). 정상 갱신은 조용하다(probe 4항).
- **자리:** 그릇 경계 `container:vllm.request.block_hashes`. `Request.update_block_hashes`를 감싸, `_all_token_ids`가 줄었을 때(세션 갱신, 토큰 pop 경로)만 마지막 저장 블록부터 대조한다. 기존 `kv_contract`의 모양(어댑터는 숫자만 넘기고 규칙은 핵심에)을 그대로 따른다.
- **비용(측정):** 마지막 블록 하나 대조 3.0 µs, 256 블록 사슬 전체 282 µs(`identity_probe.json` cost_us). 절단은 마지막 블록만 낡게 하므로 갱신마다 한 블록이면 된다. 적재 시점이 아니라 요청마다 도는 자리이므로 S4의 상시 모드 배수(1.02 이하)로 잰다.
- **다른 엔진:** SGLang의 radix 캐시는 해시가 아니라 토큰 열로 찾는다. 같은 모양의 낡음이 있는지는 재지 않았다(R4의 다음 사례 후보).

### 3.3 왜 이것이 부류 안인가

E3는 이 두 건을 "넓은 정의로는 부류 안, 캐시 정체 사실은 없음"으로 분류했다. 선언(해시 = 이 토큰들의 것)을 만드는 부품과 그것을 믿는 부품이 다르고, 각자는 제 규약 안에서 맞다. 어긋남은 선언이 시점을 잃은 것이다. `LIBRARY_DESIGN.md` 2절이 제외하는 "계층 내부의 결함"이 아니라 부품 사이의 사실이다. 반면 vllm#47282(스트림 간 경합)는 선언할 사실이 없어 범위 밖이다.

## 4. 형식·입도에서 아직 없는 사실 셋 (다음 후보, 순서는 비용 순)

| 후보 사실 | 선언하는 쪽 | 읽는 쪽 | 불변식 | 사례 | 검사 자리 |
|---|---|---|---|---|---|
| `Vocab` | `tokenizer.json`(어휘 수, 해시), `config.json`(`vocab_size`), 임베딩 행 수 | 토크나이저, 임베딩, lm_head | 세 수가 같거나, 차이가 패딩 행으로 설명됨 | transformers#48967 | 적재(정적 검사로 충분) |
| `TokenType` | 토크나이저의 특수 토큰 종류(pad, eos, bos, type id) | 패딩·마스크·cross-encoder 점수 | 패딩에 쓰인 종류가 토크나이저가 선언한 종류 | vllm#58138 | 요청 |
| `KernelConfig` | 양자화 블록 크기(`Layout.scale_granularity`) | 커널의 타일 크기 | 타일이 블록의 약수 | sglang#39626 | 적재(커널 선택) |

`Vocab`이 가장 싸다. 파일 셋을 읽어 수를 맞추는 정적 검사이고, E1의 정적 대조 틀에 바로 들어간다.

## 6. 다음 행동 (연구자가 정한다)

1. 이 초안의 다섯 부류를 블라인드 평정으로 검증한다: E3의 12건과 rolebench 16건을 F~J로 분류하고 일치도를 잰다. 평정 에이전트를 쓰면 수(2개)와 예상 사용량을 먼저 말하고 허락을 받는다.
2. `Identity`를 어휘 v5로 채택할지. 채택하면 M14로 구현한다: 핵심 규칙 `identity_stale` + vLLM 어댑터(`Request.update_block_hashes` 감쌈) + 시험 문제 둘 + 정상 실행 38개 모델 대조(S3) + 상시 비용(S4).
3. `Vocab` 정적 검사를 같은 판에 넣을지(가장 싼 어휘 확장).
