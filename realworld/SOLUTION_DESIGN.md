> **2026-09-23 재정립.** 해결 설계는 `LIBRARY_DESIGN.md`가 대신한다. 이 문서의 해법 대입(50건 중 46건 등)은 도구 없이 판단한 가상 평가다.

근거: 역할 계열 실제 버그 50건에 해법 다섯 가지를 대입한 결과(`replay_vllm_sglang.md`, `replay_transformers_llamacpp.md`, 합계 `replay_totals.json`), 비역할 대조군 20건(`replay_control.md`), 선행 연구(`prior_work.md`).

## 1. 문제 정의

LLM 추론 스택의 구성 요소(체크포인트와 설정, 모델 정의, 엔진과 스케줄러, 어텐션 커널, 양자화 패키지, 병렬화 계층, 캐시)는 텐서를 주고받는다. 텐서에는 dtype과 shape만 붙어 있고, 그 값이 무엇을 뜻하는지는 관례와 코드 경로에 흩어져 있다. 성능 최적화는 관례를 계속 늘리고, 관례가 어긋나도 숫자는 계속 흐르므로 조용히 틀린 답이 나온다.

## 2. 데이터가 알려 준 것

### 2.1 잃어버린 사실의 분포 (역할 계열 50건)

| 사실 | 건수 | 예 |
|---|---|---|
| 저장 형식 (LAYOUT) | 14 | 재배치된 가중치를 원래 형식으로 읽음, 스케일 형식 불일치, 축 역할 혼동 |
| 읽는 시점 (TIME) | 9 | 비동기 버퍼 재사용 경쟁, 낡은 CUDA Graph 재생, 빔 서치 캐시 재정렬 누락 |
| 유효 범위 (RANGE) | 8 | 청크 끝, 저장 토큰 수, 페이지 번호 공간 |
| 모델 성질 (PROPERTY) | 5 | 묶인 가중치, 공유 KV, 회전 변환, 슬라이딩 윈도 |
| 위치 기준 (FRAME) | 4 | 청크 상대 위치와 절대 위치, RoPE 기저 |
| 합산 상태 (REDUCTION) | 3 | 이미 합산된 값을 부분합으로 다시 합산 |
| 대응 관계 (MAPPING) | 3 | 설정 키 별칭, 가중치 묶음 방향 |
| 정밀도 (DTYPE) | 2 | FP8로 양자화된 입력을 BF16으로 가정 |
| 특화 가정 (새 어휘) | 1 | 컴파일 워밍업 때의 입력 모양에 그래프가 특화됨 |
| 우선순위 (새 어휘) | 1 | 사용자 명시값이 기본값에 덮임 |

**어텐션의 의미가 아니라 배관에서 대부분이 나온다.** 로더, 집합 통신, 스케줄러, 캐시 주소 계산, 벤더 커널 호출 규약이 그 배관이다. 3~4주차에 집중한 어텐션 변형 쪽은 일부다.

### 2.3 실패 분석이 요구하는 설계 조건

1. **선언은 필수여야 한다.** 실제 결함은 선언을 빠뜨리거나 틀리게 쓴 데서 나왔다. 선택 사항인 주석은 이 문제를 풀지 못한다.
2. **변형 집합은 닫혀 있고, 모든 소비자가 모든 변형을 처리해야 한다.** Intel GPU용 가중치 재배치에서 새 형식의 판독기가 4월(Q8_0)과 8월(Q2_K)에 두 번 빠졌다. 형식을 닫힌 합 타입으로 두고 처리 누락을 컴파일 오류로 만들면 이 반복이 막힌다. Rust의 망라적 match와 같은 원리다.
3. **선언은 실제 데이터로 검증되어야 한다.** 설정의 tie 플래그는 참이었지만 체크포인트에는 별도 lm_head가 있었다. 텐서의 stride는 연속처럼 보였지만 실제로는 전치되어 있었다. 적재 시점에 선언과 실제 텐서를 싸게 대조해야 한다. 증명 운반 코드의 원리(선언하고, 싸게 검사한다)를 그대로 쓴다.
4. **변환은 역할을 명시적으로 바꾼다.** 재배치는 형식 태그를, all-reduce는 부분합을 복제로, RoPE 적용은 위치 기준을 "RoPE 전"에서 "RoPE 후"로 바꾼다. 받는 쪽이 요구하는 역할과 다르면 거부된다. JAX의 샤딩 타입이 합산 상태 하나에 대해 이미 이렇게 한다.
5. **비동기 버퍼에는 소유와 시점의 규율이 필요하다.** 읽는 쪽이 붙잡고 있는 동안 쓰는 쪽이 바꾸는 형태는 Rust의 빌림 검사가 거부하는 형태다. 정적으로 다 잡기 어렵다. 실행 중 검사기가 현실적인 첫 단계다. llama.cpp의 병합되지 않은 스케줄러 검사기가 실제로 이런 경합 하나를 잡았다.
6. **특화 가정은 산출물과 함께 기록하고, 재사용할 때 다시 확인한다.** vLLM의 Qwen3-VL 사례는 워밍업 때의 가정을 다시 확인하지 않아 생겼다.
7. **생성과 누락 금지는 짝이어야 한다.** 범용 생성기가 모델 고유 규약을 표현하지 못하면 오히려 원인이 된다. transformers의 범용 토크나이저 백엔드가 명시적 토큰 번호를 다시 매긴 사례가 그렇다.

## 3. 구조: 세 층

| 층 | 무엇 | 담당 사실 | 적용 범위 근거 | 도입 |
|---|---|---|---|---|
| A. 실행 중 역할 계약 | 경계 함수와 커스텀 연산에 역할 서명을 달고, 디버그·CI 모드에서 태그를 전파하며 검사. 적재 시점 대조와 누락 금지 규칙 포함 | TIME, 청크 끝 같은 실행 중 사실, 적재 시점 사실 | S2 + S4 조합으로 50건 중 37건 | 기존 엔진에 부분 적용 가능. PyTorch는 연산 가로채기(TorchDispatchMode)와 커스텀 연산 등록, llama.cpp는 그래프 노드 태그 |

| C. 조사 문법 표면 | 사용자 언어의 조사를 역할 선언의 표면으로 쓴다. 조사는 빠질 수 없으므로 선언이 필수가 된다 | 전부 | 조건 1(필수성)을 언어 규칙으로 해결 | 장기 |

같은 선언에서 역할 기반 테스트(S3)도 생성한다. 층 A·B가 놓치는 인덱스 산술 오류 일부를 테스트가 잡는다.

> **2026-09-22 개정.** 층 C는 "역할 선언 문법"이라는 선택 단계가 되었다. "왜 라이브러리나 프레임워크나 AI가 아니라 언어여야 하는가"라는 판정 관문을 통과할 때만 만든다. 표기도 한국어가 아니라 영어(파이썬)로 한다. `RESEARCH_PLAN.md` 5.2절, 5.3절 끝, `ROADMAP.md` 4단계를 본다.

## 4. 조사 대응 스케치 (철회됨)

> **2026-09-22 철회.** 연구자의 언어 '글'의 문법 명세를 확인했다. 역할 조사는 다섯 개다. 을/를은 대상, 에는 목적지, 에서는 출처, 로/으로는 수단, 와/과는 동반이다. 부터·까지·만큼을 역할로 더하는 안은 '글'의 D-32에서 측정 후 이미 기각됐다. 격은 닫힌 작은 어휘라서 같은 역할의 인자를 구별하지 못하기 때문이다. 현재 안은 `RESEARCH_PLAN.md` 5.3절의 조사·타입 분담이다. 조사는 방향, 변환 대상, 동반만 담는다. 값의 성질(형식, 합산 상태, 위치 기준, 유효 범위, 모델 성질)은 타입이 담는다. 아래 표는 기록으로만 남긴다.

실제 의미는 사용자 언어의 규칙을 따라야 한다. 아래는 버그 데이터에서 나온 사실을 조사 후보에 대응시킨 초안이다.

| 사실 | 조사 후보 | 쓰임 예 | 검사 |
|---|---|---|---|
| 저장 형식, 정밀도 | (으)로 | "가중치를 재배치형으로 바꾼다" | 변환이 형식 타입을 바꾸고, 소비자는 모든 형식을 처리해야 함 |
| 유효 범위 | 부터, 까지 | "키를 0부터 p까지" | 포함 규칙 고정, 범위를 모르는 소비자는 오류 |
| 위치 기준 | 째, 부터 N째 | "청크 시작부터 3째" | 절대와 상대를 섞으면 오류 |
| 합산 상태 | 씩, 모두, 끼리 | "헤드를 장치마다 씩 나눈다", "끼리 합친다" | 합산은 부분합을 복제로 바꾸고, 복제를 다시 합산하면 오류 |
| 읽기와 쓰기 | 에서, 에 | "캐시에서 읽어 출력에 쓴다" | 읽는 동안의 쓰기를 거부 (빌림 규율) |
| 공유, 묶음 | 와/과 함께 | "임베딩과 함께 쓰는 출력층" | 묶음 선언과 실제 텐서 대조 |
| 원소별 독립 | 마다 | "요청마다 따로" | 배치 불변성 요구 |
| 특화 가정 | 일 때 | "배치가 1일 때 만든 그래프" | 재사용 때 조건 재확인 |
| 우선순위 | 보다, 대신 | "기본값 대신 사용자 값" | 출처 기록, 덮어쓰기 검사 |

## 5. 해법을 데이터로 보이는 다음 실험

1. **실제 버그 벤치마크:** 역할 계열 버그 12~15건을 RTX 4070 Ti에서 돌아가는 최소 재현으로 만든다. 후보는 가중치 재배치 판독기 누락, 이미 합산된 값의 재합산(단일 GPU 다중 프로세스로 모사), 청크 상대·절대 위치 혼동, 낡은 CUDA Graph 재생, 빔 서치 캐시 재정렬 누락, tie 플래그와 실제 텐서 불일치, 스케일 형식 불일치, 설정 키 별칭 누락, 컴파일 워밍업 특화다.
2. **시제품:** 층 A(실행 중 역할 계약)를 PyTorch에 먼저 만든다. rolec을 층 B의 정적 검사기로 넓힌다.
3. **측정:** 검출률, 오탐, 디버그 모드 부담, 선언을 쓰는 데 드는 코드 양을 잰다.
4. **비교:** 가장 가까운 기존 수단(JAX 샤딩 타입의 합산 상태, DTensor 배치, vLLM 백엔드 능력 표, NeMo 신경 타입)이 같은 버그를 몇 건 잡는지 함께 잰다.
5. **문제 쪽 보강:** 버그 표본을 500건 이상으로 넓히고, Ekka의 조용한 오류 90건을 같은 기준으로 다시 분류한다.
