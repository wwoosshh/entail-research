# M10 측정 정의: 공개 근거 (E1~E4)

- 작성: 2026-09-24. M10의 어떤 측정도 돌리기 전에 적었다.
- 근거: 연구자 지시(`ROADMAP.md` M10). 이 측정들은 `THEORY.md` 4.2절 명제 4와 4.6절의 빈칸을 채운다. 빈칸은 둘이다.
  - 노출도: 일반 프로젝트가 이 부류의 사고를 얼마나 자주 만나는가
  - 분모 있는 검출률: 실제 버그 가운데 몇 건을 막는가
- 이 문서는 측정의 정의만 적는다. 방향은 결과로 정한다. 결과를 보고 정의를 바꾸면 6절에 날짜와 이유를 남기고, 이미 낸 결과를 새 정의로 다시 계산한다.
- 가설과 반대되는 결과도 그대로 적는다.

- 문헌: 이슈나 사후 분석에 적혀 있다.
- 판단: 사람이 읽고 정했다.

## 1. E1 노출도 (GPU 없음)

### 1.1 대상 L: 공개 LLM

- Hugging Face API에서 `pipeline_tag=text-generation` 모델을 내려받기 수(API의 `downloads`, 최근 30일) 순으로 정렬해 앞의 300개를 쓴다. 조회 시각을 적는다.
- 모델마다 네 파일만 받는다. 가중치는 받지 않는다.
  - `config.json`
  - `generation_config.json`
  - `tokenizer_config.json`
  - `chat_template.jinja`(있으면)
- 다음 셋은 따로 센다.
  - gated
  - `config.json` 없음
  - transformers가 설정을 만들지 못함(원격 코드가 필요한 경우 등)

### 1.2 L의 측정

**L1 RoPE 덮어쓰기** (fd-rope의 원인, 코드)
- vLLM 0.30 자신의 `get_config`로 설정을 두 번 만든다. CPU에서, 가중치 없이 한다.
  - 손대지 않은 판
  - `hf_overrides={"rope_scaling": S}`를 준 판
- S는 두 가지다.
  - 모델이 `rope_scaling`을 선언하면 그 값 그대로다. 같은 값을 다시 적는 경우라서 결과가 달라지면 안 된다.
  - 선언하지 않으면 모델 카드가 긴 문맥에 쓰라고 안내하는 YaRN 값이다: `{"rope_type": "yarn", "factor": 4.0, "original_max_position_embeddings": <max_position_embeddings>}`
- 실효 RoPE 밑(base)은 이 순서로 정한다.
  1. `rope_parameters["rope_theta"]`
  2. 없으면 그 아키텍처의 vLLM 모델 파일이 `set_default_rope_theta`로 채우는 값(소스에서 읽음)
  3. 그것도 없으면 `get_rope`의 대체값 10000
- **노출:** 두 판의 실효 밑이 다르다.
- **entail 켬:** rope_alias 어댑터를 켜고 같은 일을 한다. 밑이 손대지 않은 판과 같으면 해소다.
- **교정:** Llama-3.2-3B-Instruct는 노출로 나와야 한다(실측: GSM8K 379→273). Qwen3-4B는 노출이 아니어야 한다. 둘 중 하나라도 어긋나면 L1 결과를 쓰지 않고 방법을 고친다.
- 대상은 vLLM 0.30이 아키텍처를 등록한 모델만이다. 등록되지 않은 모델은 따로 센다.

**L2 백엔드가 버리는 선언**
- `sites.check_static`(entail 1.0)을 엔진 셋(transformers, vllm, sglang)에 모두 돌린다. 능력표에 있는 백엔드를 전부 본다.
- **노출:** 모델이 선언한 성질을 버리는 (엔진, 백엔드) 쌍이 하나라도 있다. 판정이 `resolved`, `broken`, `refused` 가운데 하나인 경우다.
- 성질별로 센다(softcap, sliding window 등).
- 이것은 "그 백엔드를 고르면 버린다"는 뜻이다. 기본 백엔드가 무엇인지는 이 측정이 정하지 않는다. 기본 백엔드의 결과는 E2가 실측한다.

**L3 설정 클래스가 받지 않는 키 (Coverage)**
- `check_static`이 "받지 않음"으로 낸 키를 모두 적는다.
- 서로 다른 키마다 기계적 규칙으로 표시한다. 설치된 transformers, vLLM, SGLang의 .py 파일 어디에든 그 키 이름이 문자열이나 속성으로 나오면 "어딘가 읽음", 아니면 "읽는 곳 없음"이다.
- 해가 있는지는 판정하지 않는다.

**L4 선언의 있고 없음:** 각 사실(Template, Rotary, ModelProps의 softcap·sliding window, 양자화 Layout)을 선언한 모델 수를 센다.

### 1.3 대상 I: 단일 파일 이미지 체크포인트

- Civitai 공개 API에서 "Most Downloaded" Checkpoint 모델(전체 기간) 앞의 100개를 쓴다. 각 모델의 첫 판본에 있는 safetensors 파일이다.
- Civitai에 익명으로 접근하지 못하면 대신 Hugging Face의 text-to-image 저장소를 쓴다. 저장소 뿌리에 단일 .safetensors가 있는 것을 내려받기 순으로 100개 고른다. 어느 쪽을 썼는지 적는다.
- safetensors 머리만 읽는다(HTTP range). 가중치는 받지 않는다.

### 1.4 I의 측정

- 예측 방식 선언은 셋 가운데 하나로 분류한다.
  - (가) 상태 사전의 `v_pred` 키. ComfyUI가 읽는다.
  - (나) 메타데이터 `modelspec.prediction_type`에만 있다.
  - (다) 없다.
- v 예측 모델은 둘 가운데 하나에 해당하는 모델이다. 이렇게 세면 실제보다 적게 잡히므로 하한이다.
  - 파일이 v를 선언한다((가) 또는 (나)).
  - 모델·판본·파일 이름에 `vpred`, `v-pred`, `v_pred`, `v-prediction`이 있다(대소문자 무시).
- 노출과 entail의 판정(근거는 M6.3 실측과 entail 1.0의 판정 규칙)은 이렇다.
  - **ComfyUI 0.34.1:** `v_pred` 키가 없는 v 예측 모델이 노출이다. 이 엔진은 키만 읽는다.
  - **diffusers 0.40 단일 파일 경로:** v 예측 모델 전부가 노출이다. 이 경로는 둘 다 읽지 않는다.
  - **entail:** 파일이 v를 선언하면(가, 나) 해소한다. 아무것도 선언하지 않으면(다) "모름"을 알리고, 선언 파일이 있어야 고친다.

## 2. E2 안전성 (GPU)

### 2.1 대상

- E1-L의 목록에서 내려받기 순으로, 다섯 조건을 모두 만족하는 앞의 20개를 고른다.
  - (a) gated가 아니다.
  - (b) 원격 코드가 필요 없다.
  - (c) 세 엔진 모두에서 12 GB에 든다. bf16이면 매개변수 4.5B 이하, 미리 양자화했으면 8B 이하다.
  - (d) 채팅 템플릿이 있다.
  - (e) 세 엔진이 아키텍처를 지원한다.
- 로컬에 이미 있는 9개 모델을 더한다.
- 고른 목록과 빠진 이유를 적는다.

### 2.2 실행

- `testbed/m3_run_engine.py`를 쓴다. 프롬프트 3개, 탐욕 복호 16토큰이다.
- 각 엔진은 기본 설정으로 돌린다.
- entail은 끈 판과 켠 판(`ENTAIL=load`, 라이브러리 훅만)을 모두 돌린다.

### 2.3 측정

- **오탐:** 정상 실행에서 `broken`이나 `refused`가 나온 경우다.
  - `resolved`는 능력표의 실측 행과 대조한다. 모델이 선언한 성질을 고른 백엔드가 버린다고 실측된 행이 있으면 맞는 해소다.
  - 그런 행 없이 나온 해소는 틀린 해소로 보고 오탐에 넣는다.
- **출력:** 해소가 없는 실행에서 끈 판과 켠 판의 글이 같은가.
- **비용:** entail 자신의 시간 기록 합을 적재 시간으로 나눈다.
- **`unknown`:** 따로 센다. 오탐이 아니라 잡음으로 보고한다.
- **제외:** entail을 끈 판도 실패한 실행은 빼고 센다. 이유를 적는다.

## 3. E3 효과 (실제 버그)

### 3.1 대상

- 네 저장소의 이슈를 GitHub 검색(GET)으로 모은다.
  - vllm-project/vllm
  - sgl-project/sglang
  - huggingface/transformers
  - huggingface/diffusers
- 모으는 조건은 셋이다.
  - **기간:** 시험한 판(vLLM 0.30.0, SGLang 0.5.20, transformers 5.17.0, diffusers 0.40.0)이 PyPI에 올라간 날부터 2026-09-24까지 만들어졌다.
  - **제목:** 대규모 실증 연구의 키워드 14개(`realworld/study/README.md`) 가운데 하나가 있다.
  - **본문:** 그 판을 적었다.
- entail의 어댑터는 시험한 판에만 걸린다. 그래서 대상을 그 판으로 한정한다.

### 3.2 거르기 (판단, 원인은 보지 않음)

1. 틀리거나 품질이 떨어진 모델 출력을 보고한다. 출력은 글, 로짓, 그림, 도구 호출 인자다. 멈춤, 오류 메시지, 속도, 문서 문제는 뺀다.
2. 12 GB 한 장에서 돌 수 있다.
   - 모델은 양자화 8B 이하나 bf16 4.5B 이하다.
   - GPU 한 장이면 된다.
   - 특정 하드웨어(Blackwell, AMD, TPU 등) 전용 커널이 필요하지 않다.

- 거르기를 통과한 것이 12건을 넘으면 시드 20260924로 12건을 무작위로 뽑는다.

### 3.3 재현과 판정

- 각 건을 entail을 끄고 재현한다. 보고된 틀린 출력이 나와야 재현이다. 그다음 entail을 켜고 돌린다.
- **검출:** 둘 가운데 하나다.
  - entail이 해소해 출력이 기대대로 나온다.
  - 결함이 생긴 경계와 사실에서 `broken`이나 `refused`를 낸다.
- **모름만:** 그 자리에서 `unknown`만 낸다.
- **놓침:** 재현됐는데 entail이 통과시키거나, 그 자리에 판정이 없다.
- **재현 못 함:** 따로 센다. 이유를 적는다.
- 머리 수치는 원인 부류를 가리지 않은 전체 비율이다. 곧 재현한 출력 버그 가운데 검출한 수다. 수정 PR이 있으면 원인 설명을 옮겨 적되, 부류 판정은 머리 수치에 쓰지 않는다.

## 5. 보고와 공개 문안

- 객관적 근거(1~4절)를 먼저 적는다.
- 공개 문안의 모든 문장에는 그 문장을 받치는 수치와 파일, 근거의 종류(실측, 코드, 문헌, 판단)를 단다.
- 수치 없이 말할 수 있는 것(설계, 동작 방식)과 수치가 있어야 하는 것(효과, 비율)을 나눈다.
- 모집단 밖으로 늘려 말하지 않는다. 예를 들어 "인기 300개 가운데"를 "모든 모델"로 바꾸지 않는다.
