### Describe the bug

Any request that carries `thinking_token_budget` collapses into a degenerate repetition loop at the exact moment the budget is exhausted. Reasoning stays coherent up to the boundary, then generation turns into a single repeated token until the request-level `repetition_detection` guard ends the request with `finish_reason: repetition`.

Real-world symptom before it was isolated: an agent coding harness spawns sub-agent sessions at thinking level `low` (budget 2048), and every single sub-agent run died mid-thought, ending like this:

```text
... could be judged as beyond the message.

Hmm!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
```

with `finish_reason: "repetition"` and `usage.completion_tokens_details.reasoning_tokens == 2112` (2048 + 64) every time. Raising the level (a larger budget) made the failures disappear.

**Server command**

```bash
vllm serve XiaomiMiMo/MiMo-V2.6-Flash-RL \
  --reasoning-parser mimo \
  --generation-config vllm \
  --tensor-parallel-size 2 \
  --max-model-len 256000 \
  --speculative-config '{"method":"dflash","model":"<LOCAL_DFLASH_DIR>","num_speculative_tokens":7}' \
  --no-async-scheduling \
  --no-enable-prefix-caching \
  --compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY"}'
```

**Request**

```json
{
  "messages": [{"role": "user", "content": "<any prompt that keeps the model thinking past the budget>"}],
  "temperature": 1.0,
  "top_p": 0.95,
  "repetition_detection": {"min_pattern_size": 16, "max_pattern_size": 512, "min_count": 4},
  "thinking_token_budget": 512,
  "max_tokens": 8000,
  "stream": true
}
```

**Results** (temperature 1.0, top_p 0.95, `repetition_detection` as above):

| `thinking_token_budget` | outcome | reasoning tokens at finish | runs |
|---|---|---|---|
| absent (control) | clean answer, `finish_reason: stop` | 612 - 15999, boundary never exists | 12 |
| 8192 | clean answer, `finish_reason: stop` | 5703 (model ended thinking before the boundary) | 1 |
| 256 | `finish_reason: repetition` | 320 (256 + 64) | 1 |
| 512 | `finish_reason: repetition` | 575 / 576 (512 + 64) | 2 |
| 2048 | `finish_reason: repetition` | 2112 (2048 + 64) | 3 |

Every run whose thinking crossed its budget collapsed (6/6); no run without a budget (or without crossing it) ever did. The collapse always lands within `min_pattern_size * min_count` (16 * 4 = 64) tokens of the boundary: the repetition guard kills the request, it does not cause it. The prompt is irrelevant - a one-line question reproduces it as well as a 17k-token system-plus-task prompt.

**Suspected location**

`vllm/v1/worker/gpu/sample/thinking_budget.py`: once `num_reasoning_tokens >= budget`, `_thinking_budget_kernel` writes `1e9` into a single logit to force the next token of the `reasoning_end_token_ids` walk (`force_token_id`), and from that forced transition onward the model emits one repeated token forever. The degeneration coincides exactly with the first forced token; the forced end-of-thought sequence apparently never lands cleanly.

**Notes**

- An active reasoning config is required for the budget to take effect (`--reasoning-parser mimo` here); vLLM warns otherwise.
- Speculative decoding (dflash, 7 draft tokens) was enabled in every run below - whether it is required was not tested, because the server is a shared production instance. It may be related to #46669.
- Expected: at budget exhaustion the engine emits the end-of-thought markers and continues with the answer, `finish_reason: stop`.
