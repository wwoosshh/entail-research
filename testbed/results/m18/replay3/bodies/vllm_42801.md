### 🐛 Describe the bug

There is a substantial variance in DeepSeek R1's performance on the MMLU and HumanEval benchmarks when tested with different versions of vLLM.

I evaluated the accuracy of DeepSeek R1 on the official MMLU and HumanEval datasets using the EvalScope framework with vLLM versions 0.10.2 and 0.20.2. The results are as follows:
```
vLLM 0.10.2: MMLU 0.9895, HumanEval 0.3633
vLLM 0.20.2: MMLU 0.9123(-0.077~), HumanEval 0.5165(+0.15~)
```

There is a noticeable performance regression for DeepSeek R1 on the latest vLLM release, with a clear drop in mmlu accuracy.

I utilized the official weights and executed identical commands in both scenarios. The specific commands used to launch vLLM and evaluate the benchmark accuracy are provided below:

```
vllm serve /share_data/hf/DeepSeek-R1-FP8/ --tensor-parallel-size 8 --data-parallel-size 1  --gpu-memory-utilization 0.9 --max-model-len 32768 --trust-remote-code --dtype bfloat16 --port 8080 --enable-expert-parallel

 python tools/evaluate/evalscope/run_evalscope.py --task humaneval --model-path /share_data/hf/DeepSeek-R1-FP8/ --server-port 8080
```

Both test environments are running the same version of transformers: 4.57.1 and same evalscope version(1.7.0).

Upon inspecting the output from vLLM 0.20.2, I found that while the majority of samples on the MMLU dataset adhered to the specified prompt format ('ANSWER: X'), there were 22 instances that failed to do so. A sample of this formatting error is illustrated in the screenshot below:
