## 3. 읽은 것 (데이터이지 방향의 결정이 아니다)

1. **부류 안이면서 요청 하나로 바깥에서 보이는 것은 86건 중 5건(5.8%)이다.** 클라이언트 쪽에서 경계를 대조하는 방식(공식 DLC 후보)이 직접 닿는 몫이다. 다섯 건은 다음과 같다.
   - LM Studio `#2177`: 임베딩 모델을 LLM으로 분류해, 파일의 embedding_length와 다른 길이의 벡터를 낸다.
   - llama.cpp `#21228`: json_schema가 문법 변환에 실패하면 제약 없이 답한다(200 OK).
   - Ollama `#17562`: 토큰 한도에서 잘린 도구 호출이 완성된 것처럼 넘어가고, 중단이 성공으로 보고된다.
   - llama.cpp `#25620`: 호스트와 장치의 nwarps가 달라 NaN이 난다. 확률을 요청할 때만 보인다.
   - llama-cpp-python 서버 `#23509`: 인과 LM으로 임베딩을 요청하면 0 벡터를 낸다.
2. **규칙 1에서 따로 둔 2건이 있다.** 출력 보고가 없어 `not_output`으로 셌지만 같은 모양이다.
   - llama.cpp `#22140`: 서버가 문맥을 학습 문맥으로 조용히 자른다.
   - LM Studio `#1874`: GPU 순서 설정을 무시한다.
   - 둘을 넣어도 K1∩V1은 7/88 안팎이다.
3. **이 엔진들의 출력 오류는 대부분 하드웨어·백엔드 특유(K5 23건, 27%)이거나 원인 미상(K7 36건, 42%)이다.**
   - 백엔드: Vulkan, ROCm/HIP, SYCL, Metal, OpenCL, Hexagon.
   - 장치: AMD·Intel 내장 GPU, 모바일 GPU, 오래된 GPU.
   - llama.cpp 계열이 지원하는 장치가 넓은 만큼, 결함도 특정 장치에 몰린다.
4. **가장 큰 V 범주는 V2다(50건, 58%).** 엔진을 두 번(백엔드, 설정, 경로를 달리해) 돌려 비교해야 보인다.
   - K5의 20/23과 K7의 18/36이 여기다. "GPU에서는 틀리고 CPU에서는 맞다"가 가장 흔한 모양이다.
   - 이것은 부류(K1)를 막는 방어가 아니라 진단의 몫이다(이론 명제 6, 2.1절 4항: 어디서 깨졌는지 짚는다). entail의 명시적 안전모드와 시작 경로 점검(M19 L3.3c)도 경로를 바꿔 비교한다는 같은 생각이다.
   - 바깥에서 두 경로를 돌릴 수 있는지(예: Ollama API의 요청별 GPU 층 수 옵션)는 재지 않았다. 일반 지식이고 확인하지 않았다.
5. **부류 안 20건이 잃은 것:**
   - 토크나이저 규칙이 변환·구현에서 빠짐: 3건. 모두 V3로, GGUF에 흔적이 없다.
   - 모델 파일이 선언한 종류·구조를 엔진이 무시: 3건. 임베딩 분류, 인과 LM 임베딩, T5 인코더.
   - 가중치 저장 배치(재배열): 2건.
   - 요청·응답의 뜻: 2건. json_schema, 멈춘 이유.
   - 엔진 안 로우레벨: 6건. 그래프 재사용 키, 마스크의 인과성, 커널 설정, 큐 순서, 세션 복원 위치, K 회전.
   - 설정·이름: 3건. 텐서 분할, 장치 이름, 클라우드 별칭.
   - 패키징의 양자화 제외 목록: 1건.

## 4. 이 수를 어떻게 읽을지 (한계)

- **평정자:** 세션 한 사람이 가설을 안 채로 매겼다. 앞선 L1의 수준 판단(D/I/U)에서는 세션과 눈가림 합의의 카파가 0.939였다. 그러나 그것은 다른 질문이었고, 이번 K와 V에서도 그렇다는 보장은 없다.
- **V의 읽기:**
  - 세션은 V1을 "구조적 신호로 알아챌 수 있다"로 읽었다. 구조적 신호는 선언 대 보고, 응답 필드, 모델 메타데이터다.
  - 글이 이상하다는 내용 판단(gibberish)은 V1로 치지 않았다.
  - 특수 토큰(`[PAD]`, `<unused17>`)이 글에 나오는 경우와, 확률을 요청하면 NaN이 보이는 경우는 V1(확신 1)로 쳤다.
  - 버전을 바꿔 비교하는 것(이분 탐색)은 V2가 아니라 V4로 쳤다.
  - 눈가림 평정자는 달리 읽을 수 있다.
- **규칙 1:**
  - 연산 단위 시험 실패(모델 출력 보고 없음) 5건은 `not_output`으로 셌다.
  - 오류로 드러난 것(NaN 임베딩이 HTTP 500으로 옴)도 `not_output`으로 셌다.
  - `not_output` 64건을 이유 글의 낱말로 대략 나누면 오류·크래시·적재 25건, 연산 단위 5건, 그 밖(화면, 성능, 설치, 기능 요청, 문서) 34건이다.
- **표집:**
  - 제목 키워드로 골라서, "wrong" 같은 말 없이 보고되는 조용한 잘림은 덜 잡힌다.
  - LM Studio는 7건만 들어 수가 작다.
  - Ollama Cloud 이슈 3건이 섞였다(`#15830`, `#16111`, `#18069`).
- **판정:** 재현하지 않았다. 이슈 글과 연결된 PR 설명만 읽었다.
