# P5: 창작마당 (커스텀 노드) (제품 트랙, 2026-09-28)

- **자:** 로드맵 P5와 `LIBRARY_DESIGN.md` 8절 S10, 13.7절이다.
  - 로드맵 P5: 개발자가 작은 프로젝트에 커스텀 노드로 하이레벨 검사를 붙이고 뗀다. 커스텀 노드 SDK, 검증기, 예제 셋, 화면에서 붙이고 떼기를 만든다.
  - S10: 정상 실행에서 broken·refused가 없는가, 붙이고 떼도 핵심 시험이 그대로인가.
- **entail:** `product` 가지 `0ea75a0`(로컬)이다.

## 만든 것

- **`entail/nodes.py`(SDK, 표준 라이브러리만):**
  - 검증기는 값과 키워드 인자를 받는 보통 함수다. `nodes.ok()`, `nodes.broken(이유)`, `nodes.unknown(이유)`를 돌려준다.
  - 붙이는 곳은 `nodes.check(노드, 값, 검증기..., 인자...)`(값을 그대로 돌려줌)와 `@nodes.watch(노드, ...)`(함수의 반환값)이다.
- **판정은 핵심의 것이다.**
  - 사실 `Check`(어휘 v12), 규칙 `node_check`, 경계 `node:<노드>/<검증기>`다.
  - 통과는 세기만 한다. 어긋남은 찾은 내용마다 한 번 broken이고, 멈춤 정책이면 refused다. 판단 못 함은 unknown이다.
- **핵심이 지키는 것:**
  - 예외는 기록하고 두 번이면 뗀다.
  - 예산(기본 50 ms)을 넘으면 한 번 말하고 뗀다.
  - 검증기가 결과가 아닌 것을 돌려주면 unknown이다.
  - 디버그 모드는 예외를 올린다.
- **끄기:**
  - entail이 꺼져 있을 때, `ENTAIL_NODES=off`일 때, 기록 폴더의 `nodes.json`에서 꺼진 노드(1초 안에 다시 읽음)는 돌지 않는다.
  - 창작마당 패키지는 진입점 무리 `entail.nodes`로 붙는다. DLC와 같은 규칙을 따른다: 핵심 판 범위, `ENTAIL_NODES=이름,이름`, 진입점 이름 = 패키지 이름, 목록에 없으면 import하지 않음.
- **첫 패키지:** `workshop/basics`(`entail-nodes-basics` 0.1.0). 검증기는 `json_object`, `max_chars`, `within_context`, `same_size`다.
- **예제 셋(`examples/custom_nodes`):** 모두 모델과 GPU가 없고 `--fault`로 결함을 심는다.
  - LLM 답(JSON, 길이)
  - 검색 프롬프트의 문맥 예산
  - 이미지 크기(패키지의 검증기를 이름으로 씀)
- **플랫폼:**
  - 커스텀 노드마다 사용자 코드 흐름에 제 노드가 생긴다(기록에서 만듦). 화면은 그것을 개발자의 노드로 표시한다.
  - 화면에서 노드를 끄고 켠다. 두 번째 쓰기 `POST /api/nodes`다(안전모드 쓰기와 같은 토큰·Origin·Host 검사).
  - 커스텀 노드는 실행 목록에서 엔진으로 보이지 않는다. `entail doctor`가 창작마당 패키지를 보인다.

- 모든 실행이 끝까지 돌았다(rc 0). 결함을 심어도 프로그램은 멈추지 않는다(기본 정책).

- **비용:** 검사 한 번의 비용은 2만 번 호출의 다섯 번 중 가장 짧은 것으로 쟀다.

  | 검증기 | entail 끔 | 켬 | 검증기만 |
  |---|---|---|---|
  | 거의 아무것도 안 함 | 0.38 µs | 4.24 µs | 0.02 µs |
  | JSON 파싱(약 230자) | 0.40 µs | 5.27 µs | 0.81 µs |

- **예산 50 ms의 근거:**
  - 잰 검증기는 1 µs 안팎이고 SDK의 몫은 4~5 µs다.
  - 50 ms는 큰 출력(수 MB의 JSON)을 파싱하는 검증기에도 넉넉하다. 반면 모델이나 네트워크를 부르는 검증기처럼 요청 경로를 눈에 띄게 늦추는 것은 잡는다.
  - 이것은 판단이다. 검증기는 `@nodes.validator(budget_ms=...)`로 제 예산을 정한다.
- **화면(내장 브라우저):** LLM 예제의 결함 기록에서 사용자 코드 흐름에 커스텀 노드 둘이 보였다. `app.answer`는 깨짐(판정 1, 검사 3, 통과 2), `app.summary`는 통과였다. 알림은 "처음 깨진 곳: app.answer"였다. 스위치로 끄자 `nodes.json`에 적히고 카드가 "꺼 둠"이 됐으며, 다시 켜면 돌아왔다. 콘솔 오류는 0이었다.

## 한계

- 예제는 세션이 만든 작은 앱이다. 실제 개발자의 프로젝트에 붙여 본 것은 아니다.
- 검증기는 프로그램의 프로세스에서 프로그램의 권한으로 돈다. entail은 격리하지 않는다(설계 13.7절 신뢰 경계).
- 커스텀 노드의 이름은 기록에서 오므로, 한 번도 검사하지 않은 노드는 화면에 없다.
- 창작마당 패키지와 DLC는 PyPI에 없다(공개는 허락 뒤).

## 외부 평가(에이전트 1, 83,500 토큰)와 반영

**판정은 조건부 적합이다.** P6 전에 고칠 것 넷과 과장 지적을 받았다.

1. **검증기를 격리하지 않는다 → 위협 모델을 적고, 멈춘 검증기를 막았다(`3764d2b`, 설계 13.7절).**
   - 위협 모델: 지키는 것은 실행을 깨는 것, 핵심 규칙을 바꾸는 것, 다른 페이지의 설정 변경이다. 지키지 않는 것은 설치한 코드의 권한, 같은 컴퓨터의 다른 사용자, 이미 들어온 악성 패키지다.
   - 가장 위험한 빈틈은 돌아오지 않는 검증기였다. 예산은 호출이 돌아온 뒤에 재기 때문에, 그런 검증기가 프로그램을 멈췄다. `@nodes.validator(hard=True)`는 검증기를 데몬 스레드에서 돌리고 예산에서 기다림을 멈춘다.
   - 시험: 3초 자는 검증기가 1초 안에 제어를 돌려주고 다시 돌지 않았다.
   - 프로세스 격리는 검사당 비용 때문에 두지 않았다. 연구자 결정거리로 적는다.
2. **실제 개발자 프로젝트로 검증하라 → 하지 못했다.** 바깥 프로젝트의 코드를 받거나 연구자의 앱(ComfyUI)에 커스텀 노드 파일을 넣어야 한다. 둘 다 허락이 필요하다. 연구자 결정거리로 적는다.
3. **쓰기가 둘이 된 것을 다시 정당화하라 → 설계 13.2절에 쓰기의 규칙 넷을 적었다.** 설정 파일 하나, 엔진·코드·기록을 직접 바꾸지 않음, 되돌릴 수 있는 선택, 같은 검사다. 서버 시험이 쓰기 경로가 정확히 둘임을 지킨다(다른 여섯 경로의 POST는 404).
4. **예산을 무거운 검증기로 재라 → `testbed/p5_stress.py`, `stress.json`.**

   | 검증기 | 한 번(중앙값) | 50 ms 예산에서 |
   |---|---|---|
   | JSON 파싱 1.3 MB | 4.8 ms | 남음 |
   | JSON 파싱 13 MB | 57.5 ms | 떼어짐 |
   | 정규식 10 MB | 123.3 ms | 떼어짐 |
   | 100 ms 대기(네트워크 흉내) | 100.5 ms | 떼어짐 |

   - 수 MB까지의 파싱은 예산 안이다. 그보다 무거운 검증기는 `budget_ms`로 제 예산을 정한다.
   - `hard=True`는 호출당 84.4 µs이고, 보통 검증기는 4.8 µs다.
- **과장 지적 반영:**
  - **결함당 놓침:** 창작마당 패키지의 검증기 넷에 결함 24개(JSON 10, 문맥 5, 크기 5, 길이 4)와 좋은 값 11개를 넣었다. 24개 모두 broken으로 세어졌고 11개 모두 통과했다. 핵심이 검증기가 찾은 것을 잃지 않는다는 뜻이다. 검증기 자체가 무엇을 놓치는지는 검증기를 쓴 사람의 몫이다.
  - **패키지가 많을 때의 탐색 비용:** 가짜 패키지를 창작마당과 DLC에 같은 수만큼 두고 쟀다(한 번씩, 다섯 번 중앙값). 탐색은 프로세스당 한 번이고 entail이 켜졌을 때만 한다. 0개 조건에도 작업 사본의 창작마당 패키지 하나가 붙었다(빌드가 남긴 egg-info; 뒤에 지움).

     | 패키지 수 | 창작마당 | DLC |
     |---|---|---|
     | 0 | 1.65 ms | 1.25 ms |
     | 10 | 5.32 ms | 4.94 ms |
     | 50 | 18.46 ms | 17.40 ms |
  - **SDK 시험 보강:** 멈춘 검증기, 스레드 안의 반환과 예외, 프로그램 자신의 예외는 그대로 통과, `False`의 이유, 등록 안 된 이름, 제 예산, 쓰기 경로 둘. 전체 62개 파일 583 검사.
