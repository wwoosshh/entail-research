### 🐛 Describe the bug

* vLLM version: `v0.24.0`
* Docker image: `vllm/vllm-openai:v0.24.0`
* Model where the issue was originally observed: `google/gemma-4-31B-it-qat-w4a16-ct`
* Reasoning parser: `gemma4`

## Describe the bug

When Gemma4 thinking is enabled, the streaming and non-streaming parser paths classify the same plain output differently if the generated output contains neither `<|channel>` nor `<channel|>`.

For an output such as:

```text
This is a direct final answer without channel markers.
```

the non-streaming parser returns it as `content`, while the streaming parser returns every chunk as `reasoning` and never produces any `content`.

This can be reproduced directly against `Gemma4Parser`, without loading a model or using GPU inference.

I originally encountered this with `google/gemma-4-31B-it-qat-w4a16-ct`. With some long prompts and `enable_thinking=true`, the model occasionally produces a direct answer without generating a thought channel. Short prompts have not reproduced that model behavior reliably, but the resulting parser inconsistency itself is deterministic and can be tested independently.

Regardless of whether channel-less output is considered valid Gemma4 output, the streaming and non-streaming parser paths should classify the same generated text consistently.

## Minimal reproduction

Run this inside the `vllm/vllm-openai:v0.24.0` container:

```python
from types import SimpleNamespace

from vllm.parser.gemma4 import Gemma4Parser


class FakeTokenizer:
    bos_token_id = None
    eos_token_id = None
    pad_token_id = None

    def __init__(self):
        self._vocab = {
            "<|channel>": 100,
            "<channel|>": 101,
            "<|tool_call>": 102,
            "<tool_call|>": 103,
            "<|turn>": 104,
            "<|tool_response>": 105,
        }
        self._inverse_vocab = {
            token_id: token for token, token_id in self._vocab.items()
        }

    def get_vocab(self):
        return self._vocab

    def decode(self, token_ids):
        return "".join(
            self._inverse_vocab.get(token_id, f"<token:{token_id}>")
            for token_id in token_ids
        )


def dump_delta(delta):
    if delta is None:
        return None

    if hasattr(delta, "model_dump"):
        return delta.model_dump(exclude_none=True)

    return {
        name: value
        for name in ("reasoning", "content", "tool_calls")
        if (value := getattr(delta, name, None)) is not None
    }


tokenizer = FakeTokenizer()
request = SimpleNamespace(
    tools=None,
    tool_choice=None,
)

plain_answer = "This is a direct final answer without channel markers."

print("=== Non-streaming ===")

nonstream_parser = Gemma4Parser(
    tokenizer,
    chat_template_kwargs={"enable_thinking": True},
)

reasoning, content = nonstream_parser.extract_reasoning(
    plain_answer,
    request,
)

print({
    "reasoning": reasoning,
    "content": content,
})


print("\n=== Streaming ===")

stream_parser = Gemma4Parser(
    tokenizer,
    chat_template_kwargs={"enable_thinking": True},
)

# Simulate a normal chat-template prompt ending at a new model turn.
prompt_token_ids = [
    tokenizer.get_vocab()["<|turn>"],
]

chunks = [
    "This is a",
    " direct final answer",
    " without channel markers.",
]

for index, chunk in enumerate(chunks):
    delta = stream_parser.parse_delta(
        delta_text=chunk,
        delta_token_ids=[],
        request=request,
        prompt_token_ids=prompt_token_ids if index == 0 else None,
        finished=False,
    )
    print(f"chunk {index}:", dump_delta(delta))

final_delta = stream_parser.parse_delta(
    delta_text="",
    delta_token_ids=[],
    request=request,
    prompt_token_ids=None,
    finished=True,
)
print("finished:", dump_delta(final_delta))
```

## Actual output

```text
=== Non-streaming ===
{'reasoning': None, 'content': 'This is a direct final answer without channel markers.'}

=== Streaming ===
chunk 0: {'reasoning': 'This is a'}
chunk 1: {'reasoning': ' direct final answer'}
chunk 2: {'reasoning': ' without channel markers.'}
finished: None
```

## Expected behavior

The streaming result should be consistent with the non-streaming result.

For generated output containing neither `<|channel>` nor `<channel|>`, the expected combined result is:

```python
{
    "reasoning": None,
    "content": "This is a direct final answer without channel markers.",
}
```

If channel-less output is instead considered malformed, both parser paths could report or handle it as malformed output. However, one path should not classify it as final content while the other silently classifies the entire output as reasoning.

## Suspected cause

With `enable_thinking=true`, `Gemma4Parser.is_reasoning_end()` returns `False` when the prompt ends with the new-turn token:

```python
if new_turn_id is not None and tid == new_turn_id:
    return not self._thinking_enabled
```

`adjust_initial_state_from_prompt()` then initializes the streaming parser in `ParserState.REASONING`:

```python
if self.is_reasoning_end(list(prompt_token_ids)):
    return

self._engine.reset(initial_state=ParserState.REASONING)
self._streaming_initialized = True
```

This works when the model follows the expected format and generates a reasoning channel followed by `<channel|>`.

However, if the generated text contains no channel markers, the streaming parser never receives an event that transitions it back to `ParserState.CONTENT`, so all text chunks are emitted as reasoning.

The non-streaming parser processes the completed output from its default content state and therefore returns the same text as content.

The prompt-based state initialization was introduced to support prompts that actually end inside an open reasoning channel. The current behavior also treats a normal new model turn with thinking enabled as already being inside reasoning, before a generated `<|channel>` token has been observed.

## Possible approaches

Possible ways to make the two paths consistent include:

1. Initialize `ParserState.REASONING` only when the prompt actually ends inside an open `<|channel>` block.
2. Use an undecided initial streaming state for a normal new model turn and enter reasoning only after observing a generated `<|channel>` token.
3. Buffer initial plain-text chunks until the parser can determine whether a reasoning channel is being opened.
4. Define channel-less output as malformed and handle it consistently in both streaming and non-streaming parsing.

A regression test based on the reproduction above would cover this case without requiring a model or a long prompt.
