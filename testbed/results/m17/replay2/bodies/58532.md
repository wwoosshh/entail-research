### 🐛 Describe the bug

`QuarkW8A8Int8MoEMethod` supports static per-tensor activation scales
together with per-output-channel weight scales. However, the legacy
Triton MoE path uses the activation quantization flag to select both
activation-scale and weight-scale indexing.

For this combination, `per_act_token_quant=False`, so the kernel takes
the tensor-scale branch even though the weights have per-channel scales.
It consequently reads the weight scales using the wrong layout.

This affects the existing static INT8 path independently of its planned
migration to the MoE oracle.

### Expected behavior

Activation and weight scales should be indexed independently:

- A1/A2: use the loaded static scalar activation scales.
- W13/W2: use the scale belonging to the routed expert and output channel.

Changing relevant weight scales should affect the corresponding
computation, while changing scales belonging only to unrouted experts
should not affect the output.

### Observed behavior and reproduction outline

A component probe used:
- 4 experts
- Hidden size and intermediate size of 128
- 8 tokens, top-k=2
- BF16 inputs
- Static activation scales and nonuniform per-channel weight scales
- No bias, with router weights applied on the output side

The probe exercised Quark weight creation and post-load processing,
then its existing `apply()` path.

With fixed weights, inputs, and routing, multiplying all W13 channel
scales of expert 3 by 4 produced no output change, although that expert
was selected by four routing slots.

An experimental patch separating weight-scale layout from activation
quantization made this perturbation affect the output. The corrected
legacy and manually constructed modular paths also produced identical
BF16 outputs for the covered case.

These are component-level observations, not a completed model evaluation
or full regression result. The modular comparison bypassed backend
selection and does not establish static INT8 oracle support.

### Suspected root cause

There are two related problems:

1. `int8_w8a8_moe_quant_config()` currently sets
   `per_out_ch_quant=False`.
2. The legacy wrapper and `TritonExperts` pass
   `per_act_token_quant` as the GEMM kernel's `per_channel_quant` flag.

In the shared non-block W8A8 kernel, that flag selects both per-token
activation-scale reads and per-channel weight-scale reads. The tensor
branch instead loads one activation scale and indexes the weight scale
as one scalar per expert.

Relevant code at the inspected revision:
- [INT8 quant-config factory](https://github.com/vllm-project/vllm/blob/00b7847c8036b667742b4efb21aab1de51fd4721/vllm/model_executor/layers/fused_moe/config.py#L628)
- [Shared scale indexing](https://github.com/vllm-project/vllm/blob/00b7847c8036b667742b4efb21aab1de51fd4721/vllm/model_executor/layers/fused_moe/fused_moe.py#L483)
- [Legacy config forwarding](https://github.com/vllm-project/vllm/blob/00b7847c8036b667742b4efb21aab1de51fd4721/vllm/model_executor/layers/fused_moe/fused_moe.py#L1619)

### Proposed fix

I propose separating activation-scale and weight-scale indexing in the
shared INT8/FP8 non-block Triton path, using the independent granularity
information already represented by `FusedMoEQuantConfig`.

This would include propagating both flags through the call chain and
correcting callers that currently rely on the coupled behavior without
explicitly declaring their actual weight-scale layout.

The scope would remain scale layout and indexing. Block quantization,
quantization algorithms, backend selection, compute dtype, and
router-weight ordering would retain their existing behavior.

FP8 is part of the compatibility and regression scope because it shares
this implementation; I am not reporting a separately reproduced FP8
failure here.

### Related issue

Related to #57092, which fixes per-token activations with per-tensor
weight scales. This report concerns the opposite combination:
per-tensor activations with per-channel weight scales, reproduced
through Quark static INT8.

That combination remains skipped in #57092's updated combination tests.
The proposed fix would preserve its stride/broadcast corrections while
separating activation-scale and weight-scale indexing.

This is also a correctness prerequisite for the Quark static INT8
oracle migration tracked in #54959.

I would like to submit this correctness fix separately, followed by the
static INT8 oracle migration.

```python
"""Deterministic component reproducer for vllm-project/vllm#58532.

Run with a working CUDA vLLM installation; no checkpoint is downloaded.
This uses Quark's static legacy path, including create/post-load/apply.
It does not patch vLLM, bypass selector checks to construct a modular kernel,
or validate a full model. Nonzero exit means a failed assertion or runtime error.

The weights are INT8 identity matrices (gate, up, and down). With x=1,
A1=A2=1/16 and weight scales=1, each expert returns 12/16 = 0.75:
  GEMM1 -> gate=up=1; SiLU(1)*1 -> BF16 -> INT8 value 12.
Top-k=2 with weights 0.5 preserves 0.75 after reduction.

Doubling only expert 3's gate channel 0 scale gives gate=2, up=1;
SiLU(2)*1 -> BF16 -> INT8 value 28, hence expert output 28/16=1.75.
Rows routed to expert 3 therefore have output[0] = (1.75+0.75)/2 = 1.25.
Doubling its down-projection channel 0 scale instead gives 1.125 there.
All these final values are exactly representable in BF16. The tested values
are away from INT8 rounding ties and saturation, so exact checks are intended.

This newly prepared script has not yet been GPU-validated. It replaces the
earlier random sensitivity probe with a hand-checkable construction.
"""

import json
import subprocess
from pathlib import Path

import torch

import vllm
from vllm.config import VllmConfig, set_current_vllm_config
from vllm.model_executor.layers.fused_moe.activation import MoEActivation
from vllm.model_executor.layers.fused_moe.config import (
    FusedMoEConfig,
    FusedMoEParallelConfig,
    RoutingMethodType,
)
from vllm.model_executor.layers.quantization.quark.quark_moe import (
    QuarkW8A8Int8MoEMethod,
)
from vllm.model_executor.layers.quantization.utils.quant_utils import (
    kInt8StaticChannelSym,
    kInt8StaticTensorSym,
)
from vllm.v1.worker.workspace import init_workspace_manager


def emit(**values):
    print(json.dumps(values), flush=True)


@torch.inference_mode()
def run():
    device = torch.device("cuda:0")
    dtype = torch.bfloat16
    experts, hidden, intermediate, tokens, topk = 4, 128, 128, 8, 2
    init_workspace_manager(device)
    config = FusedMoEConfig(
        num_experts=experts,
        num_local_experts=experts,
        num_logical_experts=experts,
        experts_per_token=topk,
        hidden_dim=hidden,
        intermediate_size=intermediate,
        activation=MoEActivation.SILU,
        device="cuda",
        routing_method=RoutingMethodType.Default,
        moe_parallel_config=FusedMoEParallelConfig.make_no_parallel(),
        in_dtype=dtype,
        has_bias=False,
        moe_backend="triton",
        max_num_tokens=tokens,
    )
    method = QuarkW8A8Int8MoEMethod(
        config, kInt8StaticChannelSym, kInt8StaticTensorSym
    )
    layer = torch.nn.Module()
    layer.intermediate_size_per_partition = intermediate
    layer.local_num_experts = experts
    layer.global_num_experts = experts
    layer.activation = MoEActivation.SILU
    layer.expert_map = None
    layer.apply_router_weight_on_input = False
    with torch.device(device):
        method.create_weights(layer, experts, hidden, intermediate, dtype)

    eye = torch.eye(hidden, dtype=torch.float32, device=device).to(torch.int8)
    layer.w13_weight.copy_(torch.cat((eye, eye), dim=0).unsqueeze(0))
    layer.w2_weight.copy_(eye.unsqueeze(0))
    layer.w13_weight_scale.fill_(1.0)
    layer.w2_weight_scale.fill_(1.0)
    layer.w13_input_scale.fill_(1.0 / 16)
    layer.w2_input_scale.fill_(1.0 / 16)
    method.process_weights_after_loading(layer)
    if method.moe_kernel is not None:
        raise RuntimeError("This reproducer targets the static legacy path before PR B")

    x = torch.ones((tokens, hidden), dtype=dtype, device=device)
    # Expert 3 receives four slots; expert 2 receives none.
    ids = torch.tensor([[3, 1], [0, 1]] * 4, dtype=torch.int32, device=device)
    weights = torch.full((tokens, topk), 0.5, device=device)
    routed_to_3 = (ids == 3).any(dim=1)
    expected_base = torch.full_like(x, 0.75)
    failures = []

    def forward():
        result = method.apply(layer, x.clone(), weights, ids, None, None)
        torch.cuda.synchronize()
        return result.clone()

    def check(name, actual, expected):
        emit(
            case=name,
            actual_channel_0=actual[:, 0].float().tolist(),
            expected_channel_0=expected[:, 0].float().tolist(),
            max_abs_error=(actual.float() - expected.float()).abs().max().item(),
        )
        try:
            torch.testing.assert_close(actual, expected, rtol=0, atol=0)
        except AssertionError as error:
            failures.append(name)
            print(f"FAIL {name}: {error}", flush=True)
        else:
            print(f"PASS {name}", flush=True)

    baseline = forward()
    check("baseline", baseline, expected_base)
    check("repeatability", forward(), baseline)
    for attr, expected_value in (
        ("w13_weight_scale", 1.25),
        ("w2_weight_scale", 1.125),
    ):
        scale = getattr(layer, attr)
        saved = scale.clone()
        try:
            scale[3, 0].mul_(2)
            expected = expected_base.clone()
            expected[routed_to_3, 0] = expected_value
            check(f"{attr}: routed expert 3, channel 0 x2", forward(), expected)
        finally:
            scale.copy_(saved)
        try:
            scale[2].mul_(4)
            check(f"{attr}: unrouted expert 2 x4", forward(), expected_base)
        finally:
            scale.copy_(saved)

    if failures:
        emit(result="FAIL", failed_cases=failures)
        raise SystemExit(1)
    emit(result="PASS")


if __name__ == "__main__":
    if not torch.cuda.is_available():
        raise RuntimeError("A CUDA GPU and a working CUDA vLLM installation are required")
    source_dir = Path(vllm.__file__).resolve().parent
    revision = subprocess.run(
        ["git", "-C", str(source_dir), "rev-parse", "HEAD"],
        capture_output=True,
        text=True,
        check=False,
    )
    emit(
        torch=torch.__version__,
        cuda=torch.version.cuda,
        vllm_version=vllm.__version__,
        vllm_file=str(vllm.__file__),
        source_git_head=revision.stdout.strip() if revision.returncode == 0 else None,
        gpu=torch.cuda.get_device_name(0),
    )
    with set_current_vllm_config(VllmConfig()):
        run()
```
